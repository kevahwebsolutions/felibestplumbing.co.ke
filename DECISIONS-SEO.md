# SEO decisions

1. **No address, geo or priceRange in the business markup.** The site has no street address or coordinates and the owner asked not to invent them. The previous markup carried a locality-only `PostalAddress` and `priceRange: "KES"`; both were removed. `areaServed` lists Nairobi and the areas on the coverage page.
2. **No Review or AggregateRating.** The testimonials look like template content (one reviewer appears three times, two with identical text), so review markup would break Google policy. The audit fails any page that contains `aggregateRating` or `review`. Owner task: collect real reviews first.
3. **Organization and Plumber are separate entities.** Organization carries the logo (512 px PNG), `sameAs` and `contactPoint`; the Plumber business references it through `parentOrganization`. Both sit in one `@graph` in the root layout, so every page carries them once and pages reference them by `@id`.
4. **WebSite has no SearchAction** because the site has no search results page. `availableLanguage` is English only.
5. **Titles.** Pages pass a short topic; the helper adds ` | Felibest Plumbing` only when the result is at most 60 characters. Long category titles (for example "Washing Machine Covers and Stands in Nairobi") drop the suffix instead of being cut. The home page uses a finished title.
6. **Descriptions are hand-written** for services, posts and static pages, and unit tests hold them to 110-155 characters. Category descriptions are the catalogue intro plus the longest tail that fits.
7. **Canonical and variants.** Canonical is always the clean path; `/shop?category=x` canonicalises to `/shop`. There is no pagination. Query variants are also disallowed in robots.txt (`?category=`, `?sort=`, `?q=`). `alternates.languages` is omitted (one language).
8. **Open Graph images are JPEG routes**, not static WebP files, because WhatsApp and several crawlers do not render WebP previews. The text in the band is rendered by sharp through SVG, so on a server with no fonts only the logo shows; the layout still works.
9. **robots.txt does not use `Host:`** (not a standard directive). It explicitly allows `/og/`, `/_next/static/`, `/_next/image`, `/images/` and `/media/` so crawlers can render pages and fetch share images.
10. **Sitemap dates.** Static pages use the git commit date of their source files, written to `src/data/lastmod.json` by `npm run build` (`prebuild`). When git is unavailable (the server) the committed file is used. Services share one date because the services data is a single file. The sitemap stays one file: about 70 URLs, far below the 500 URL split threshold.
11. **404 for dynamic slugs.** In this Next.js version (16.4), `notFound()` thrown inside a dynamic page answers 404 with the `noindex` tag but sends an empty HTML shell, and client JavaScript draws the not-found UI. For services and blog the slugs are static data, so `src/proxy.ts` rewrites unknown slugs to an unmatched path, which Next renders fully on the server. For products and categories (database-backed) the status and noindex are correct but the body is client-rendered; the audit checks status and noindex only for `/shop/...` 404s. A proxy lookup against SQLite was rejected as too risky for the standalone build.
12. **Image weight is measured the way a phone loads it.** The audit picks the `srcset` entry a 412 px screen would download (using the `sizes` attribute) instead of the 1920 px `src` attribute, which overstates weight by 3-4x.
13. **Performance is not targeted.** Lighthouse mobile performance is bound by main-thread JavaScript (long "element render delay"), not by images or the server. It was not changed here; see `docs/LIGHTHOUSE-SEO.md`.
14. **Sitemap and robots are built from `NEXT_PUBLIC_SITE_URL` at build time.** `robots.txt` is prerendered, so the production build must run with the production URL (the audit does this explicitly; the local `.env` points at localhost).
15. **Blog dates.** `updated` is optional and shown only when it differs from the publish date; `dateModified` falls back to the publish date. No dates were invented.
