# Catalogue decisions

1. **Categories (6), plain names.** Showers (Milano shower); Pumps (DDA 1000P); Washing Machine Plumbing (tap, inlet pipe, outlet pipe); Washing Machine Covers and Stands (three covers, stand); Laundry Bags (shoe bags, zipped bags, drawstring bags); Laundry Care (scent beads, pods, colour and dirt catcher, drum cleaning tablets). The owner can rename them in the admin. Intro text for each is written only from the real products.
2. **Three covers stay separate products.** Slugs `front-load-washing-machine-cover-kes-800`, `-kes-1000`, `-kes-1200` (the catalogue gives only the price to tell them apart; no size is invented). Names are exactly as in the CSV. Page titles carry the price for uniqueness. They appear first in each other's related products. The slug can be edited in the admin if prices change.
3. **List prices are internal.** The struck-through higher prices are stored only in `list_price_note`, shown in the admin form, never rendered, never in JSON-LD. No "was" price, no sale badge. The existing `sale_price` admin feature is untouched and unused.
4. **Stock unknown.** New `track_stock` flag, off for all imported products. They show "Available to order" and `InStock`. Orders only check and decrement stock when counting is switched on for a product. Low-stock alerts and cancel-restock respect the flag.
5. **Descriptions.** Rows 1, 2, 3 and 5 use the supplier text unchanged, only displayed as a lead line plus bullets (words untouched). Their text contains a supplier price ("Price: KSh ...") and, for row 3, the Beta Supplies phone number and location. They are kept as instructed and flagged in the owner tasks. Twelve descriptions are generated from name, photos and category only, `descriptionStatus: generated-from-name`, `needsReview: true`. The admin shows "Description to be confirmed"; customers never see it. Editing the description in the admin clears the flag.
6. **Images.** 29 of 41 kept. Excluded: two AI-watermarked Milano flat-lays, six photos with handwritten prices where a clean one exists, two stock-style images, plus two more handwritten-price photos (see docs/catalog-images.md). Exceptions where only marked photos exist are kept and listed there. All are low resolution screen captures and are flagged.
7. **Card and gallery layout.** Photos are portrait, so cards use a 4:5 frame and the product gallery shows the whole photo (`object-contain`).
8. **Import identity.** Real products are matched by a catalogue key stored in `import_snapshot`, so editing a slug in the admin does not create duplicates. A field is only updated when the database still equals the last imported value, so owner edits survive. Old sample products are recognised by a fixed slug list (plus the local `laundry-pods` duplicate); any other product is left alone unless `--prune-unknown` is passed, so products the owner adds later are never archived by a deploy.
9. **Old rows.** Referenced rows are archived (hidden everywhere, order history intact; a row that shared a real slug is renamed `...-legacy-<id>`). Unreferenced rows are deleted. Empty legacy categories are deleted. The unused sample images in `public/images/product` were removed.
10. **Per-product SEO.** Full page titles (30 to 60 characters) bypass the site title template. Meta descriptions 110 to 155. JSON-LD: Product + Offer (price, KES, availability, url, image) with no priceValidUntil, ratings or SKU; brand only if an admin adds a Brand spec (none imported, to stay conservative). BreadcrumbList includes the category.
11. **Install cross-sell** only for Showers, Pumps and Washing Machine Plumbing.
12. **Shop page** now renders products on the server (no skeleton), uses the real price range, and links to category pages. Category pages are at `/shop/category/[slug]`.
13. **Local working-tree change.** The uncommitted simplification of `src/app/og/product/[slug]/route.ts` present at the start was kept and committed as part of this work; it passes the share-image tests.
14. `next-env.d.ts` (auto-generated) was not committed.
